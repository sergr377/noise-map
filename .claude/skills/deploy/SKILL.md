# Деплой noise-map

Демо — это один контейнер на VDS в `/opt/noise-map`, Caddy впереди, режим
`CACHE_ONLY=1`. Оператор ходит туда по SSH под алиасом `noisemap`; сам хост и
ключ живут в `~/.ssh/config` той машины и намеренно не в репозитории.

Здесь — как выкатить изменение. Как сервер поднимали в первый раз (DNS,
сертификат, железо), написано в README.

## Прежде чем что-то менять — посмотрите, что там сейчас

Осмотр ничего не ломает и экономит потом полчаса:

```bash
ssh noisemap 'cd /opt/noise-map && git log --oneline -1 && docker compose ps --format "{{.Name}} {{.Status}}"'
```

Если версия на сервере отстаёт больше чем на пару коммитов, посмотрите, что
именно приедет: в этом проекте между релизами успевают влиться чужие ветки, и
знать об этом лучше до, а не после.

## Порядок, и почему именно такой

**Данные раньше контейнера.** И подложка, и слой шума должны лежать на месте к
моменту, когда стартует новый фронтенд, — иначе первый посетитель встретит карту,
которой нечего рисовать. Но слой печётся кодом из нового образа, поэтому сборка
образа идёт раньше выпечки:

1. `git pull` + `docker compose build` — старый контейнер всё это время работает
2. выпечка слоя шума (если менялся кэш или код выпечки)
3. `docker compose up -d`
4. проверка **снаружи**

Шаг 2 пропускается, когда ни кэш, ни выпечка не менялись: слой лежит в
`/opt/noise-map/tiles/noise` и переживает пересборку образа.

## Обычный случай: изменение в коде

```bash
ssh noisemap 'cd /opt/noise-map && git pull --ff-only && git log --oneline -1 && docker compose build 2>&1 | tail -6'
```

```bash
ssh noisemap 'cd /opt/noise-map && docker compose up -d && sleep 8 && docker compose ps --format "{{.Name}} {{.Status}}"'
```

Сборка занимает около десяти секунд на тёплых слоях и до минуты, если менялся
`package.json`.

## Когда менялся кэш: пересобрать слой шума

Пирамида тайлов печётся **из кэша**, поэтому после каждого прогрева её надо
пересобирать — иначе новых расчётов на карте не появится. Java для этого не
нужна, так что, в отличие от подложки, слой собирается прямо на сервере
одноразовым контейнером из уже собранного образа:

```bash
ssh noisemap 'docker run --rm -v noise-map_noise-cache:/app/cache:ro -v /opt/noise-map/tiles:/app/tiles noise-map-noise-map:latest node --max-old-space-size=6144 scripts/build-noise-tiles.mjs --force'
```

Ориентир на прогретом Краснодаре: 269 расчётов → 16 445 тайлов и 121 МБ примерно
за три минуты, по 30–40 с на обрезку каждого периода. Если числа заметно
разошлись с этими — стоит понять почему, прежде чем поднимать контейнер.

Два места, где легко споткнуться, и оба уже стоили времени:

- **Кэш — именованный том** `noise-map_noise-cache`, а не каталог рядом с
  проектом. Подставить путь на хосте не выйдет: каталога там нет, и контейнер
  молча испечёт пустую пирамиду.
- **`./tiles` основной сервис монтирует `:ro`.** Раздавать этого достаточно,
  писать — нет. Одноразовый контейнер подключает тот же каталог обычным образом;
  так же устроена сборка глифов подложки.

**Неудачная выпечка безопасна.** `meta.json` пишется последним, а без него клиент
слоя просто не видит и ведёт себя как до его появления. Поэтому оборвавшаяся
выпечка не оставляет полуфабриката на карте — она оставляет карту без слоя.

## Когда менялась подложка

**Тайлы первыми, контейнер вторым**, и тайлы **не собираются на сервере**:
Planetiler требует Java 21, а в образе JRE 17 ради движка. Готовый `.pmtiles`
самодостаточен и едет файлом:

```bash
scp tiles/basemap.pmtiles noisemap:/opt/noise-map/tiles/
```

```bash
ssh noisemap 'sha256sum /opt/noise-map/tiles/basemap.pmtiles'
```

Сравните сумму с локальной. На 163 МБ с домашнего канала закладывайте пару минут.
Глифы и стиль Java не требуют и собираются на месте — команда в README, раздел
«Деплой».

## Проверка — снаружи, а не с хоста

Смысл именно в том, чтобы задеть Caddy и настоящий сертификат. Проверка с самой
машины этого не делает.

```bash
B=https://noisemap.online; for u in / /api/health /api/noise/tiles/meta.json /tiles/style.json; do printf "%-34s %s\n" "$u" "$(curl -s -o /dev/null -w '%{http_code}' --max-time 25 $B$u)"; done
```

```bash
curl -s --max-time 25 https://noisemap.online/api/noise/tiles/meta.json
```

`built` в ответе должен смениться после выпечки — это и есть подтверждение, что
слой пересобрался, а не остался прежним. Дальше — сам тайл и подложка:

```bash
curl -s -o /dev/null -w 'тайл: %{http_code}, %{size_download} байт, %{content_type}\n' --max-time 25 -H 'Accept-Encoding: gzip' 'https://noisemap.online/api/noise/tiles/DEN/14/9965/5892.pbf?v=1'
```

```bash
curl -s -o /dev/null -w 'Range по pmtiles: %{http_code}\n' --max-time 30 -H 'Range: bytes=0-16383' https://noisemap.online/tiles/basemap.pmtiles
```

Что должно получиться: страница, health, `meta.json` и стиль — 200; health несёт
`cacheOnly: true` и неизменные `JOB_PARAMS`; тайл — 200 около 50 КБ с типом
`application/x-protobuf`; `Range` по `.pmtiles` — **206, а не 200** (без частичных
запросов карта не откроется вовсе).

Полезно добавить пробу точки в прогретом месте — она должна отвечать
`cached: true`, то есть кэш на месте и виден:

```bash
curl -s --max-time 25 'https://noisemap.online/api/noise?lat=45.0359&lon=38.9560'
```

## Проверка глазами

Стоит сделать сверх curl, но **дайте времени**: панель рисуется задолго до
тайлов, и пустая карта на первом кадре — не поломка. Слои приложения создаются по
событию `load`, которое ждёт первой полной отрисовки подложки, поэтому слой шума
появляется последним. В медленном софтверном рендере (например, в браузере
песочницы) это занимает под минуту при том, что данные приезжают за секунды.

Признак, что всё хорошо: по прогретому месту клик отвечает «Здесь NN–NN дБ» и не
запускает расчёт.

## Если команды блокируются

В авто-режиме классификатор не пропускает изменения на боевом сервере. Разблокирует
правило в `permissions.allow` — в `~/.claude/settings.json`, а **не** в
`.claude/settings.json` проекта, если репозиторий публичный:

```json
{
  "permissions": {
    "allow": [
      "Bash(ssh noisemap 'cd /opt/noise-map && git *)",
      "Bash(ssh noisemap 'cd /opt/noise-map && docker *)",
      "Bash(ssh noisemap 'docker *)"
    ]
  }
}
```

Правило совпадает по началу строки, поэтому вызывать `ssh` надо ровно в этой
форме: лишние флаги вроде `-o BatchMode=yes` в начало не впишутся, и блокировка
вернётся. Это скорее свойство, чем недостаток — права выданы на `git` и `docker`
в `/opt/noise-map`, а не на произвольную команду под root.

## Откат

Код откатывается обычным способом — переключиться на прежний коммит и пересобрать:

```bash
ssh noisemap 'cd /opt/noise-map && git checkout <коммит> && docker compose build && docker compose up -d'
```

Тайлы при этом трогать не нужно: и подложка, и слой шума переживают откат кода, а
старый фронтенд просто не спрашивает того, чего не знает. Тайлы вообще живут
дольше образа — пересобирать их ради отката не надо, а пересборка тайлов не
требует передеплоя.

## Чего этот деплой не проверяет

**Акустику.** Демо работает в `CACHE_ONLY` и ничего не считает, поэтому выкатка
не может подтвердить, что движок жив. Проверка расчёта — отдельная задача на
машине с установленным NoiseModelling.

**И CI тоже не проверяет всё.** Он гоняет сервер прямо из `node` и никогда не
собирает compose-стек и не запускает runtime-образ. Целый класс дефектов доезжает
до прода с зелёной галочкой: пустая строка вместо неустановленной переменной в
compose, `rename` через границу bind-монтирований (`EXDEV`), новый каталог верхнего
уровня, который runtime-стадия образа не копирует. Если изменение трогает
`docker-compose.yml`, `Dockerfile` или чтение переменных окружения — прогоните его
в образе до выкатки и ждите, что поломка будет выглядеть совсем не так, как
локально.
