# CLAUDE.md

Карта шумового загрязнения: OpenStreetMap → CNOSSOS-EU → изофоны на Яндекс Картах.
Подробности для людей — в [README.md](README.md). Здесь то, что нужно знать, чтобы
работать с этим кодом и не наступить на уже пройденные грабли.

## Команды

```bash
npm run server      # сборка TS + API на :8787 (отдаёт и dist-web, если собран)
npm run web         # Vite на :5174, /api проксируется на :8787
npm run typecheck   # сервер и фронт, оба strict
npm run build:web

node scripts/run-job.mjs --lat 55.7649 --lon 37.6055   # расчёт напрямую, без API
node scripts/sanity-check.mjs <geojson> DEN            # не потерялось ли экранирование
node scripts/compare-runs.mjs <a> <b> DEN              # сравнить два прогона по площади
node scripts/rail-probe.mjs <lat> <lon>                # что OSM знает о путях вокруг точки

# требуют собранного сервера (npm run build:server):
node scripts/check-quantize.mjs                        # идемпотентность сетки кэша

# требуют запущенного API на :8787:
node scripts/prewarm.mjs moscow                        # прогреть кэш демо-точек
node scripts/smoke-api.mjs                             # сквозная проверка HTTP-слоя
```

`inspect_db.groovy` выгружает схему таблиц из базы прогона — им выясняется, что
на самом деле создал тот или иной блок NoiseModelling:

```bash
NM_TABLES=LW_RAILWAY,ROADS .tools/nm/NoiseModelling_6.0.0/bin/ScriptRunner \
  -w jobs/<id> -s pipeline/inspect_db.groovy
```

## Расчёт дорогой — это влияет на всё

Холодный расчёт занимает **3–10 минут на всех ядрах и до 1.8 ГБ**. Отсюда:

- **`POST /api/noise` не является проверкой — он запускает вычисление.** Узнать,
  посчитано ли место, не начав считать, сейчас нельзя. На этом легко случайно
  занять машину на полчаса.
- Не запускайте расчёты «на всякий случай». Для проверок используйте прогретые
  точки: Тверская `55.7649,37.6055`, Садовое `55.7708,37.6335`, Хамовники
  `55.7315,37.5806`.
- Долгие прогоны запускайте фоном и не опрашивайте чаще, чем раз в десятки секунд.

## Окружение

- **Java обязательна.** Дистрибутив NoiseModelling лежит в `.tools/` (148 МБ, не
  в git). Байткод собран под Java 11, локально работает на JDK 25.
- **Node 22 не читает `HTTPS_PROXY` для `fetch`.** На этой машине поднят локальный
  прокси, и без него часть хостов выглядит мёртвой. Диспетчер ставится в
  `scripts/lib.mjs` и `server/src/config.ts` — **любой новый код, который куда-то
  ходит, должен импортировать `lib.mjs` или сам поставить `ProxyAgent`.**
- **Docker собрать здесь нельзя**: виртуализация выключена в BIOS, прав
  администратора нет. `Dockerfile` написан, но ни разу не собирался.
- Лаунчер движка называется по-разному: `ScriptRunner.bat` на Windows,
  `ScriptRunner` на Linux. Выбор по `process.platform` уже есть — не захардкодьте
  обратно.

## Ключи и секреты

Ключей **два разных**, они не взаимозаменяемы:

- `VITE_YANDEX_API_KEY` — JavaScript API, карта. Vite вшивает его в бандл на
  сборке; это нормально, он ограничен по HTTP Referer.
- `YANDEX_GEOCODER_KEY` — HTTP Геокодер, поиск. **Без префикса `VITE_` намеренно**:
  ограничения по referer у него нет, в браузер он попасть не должен. Фронт ходит
  через `/api/geocode`.

Перед каждым коммитом:

```bash
git grep -n --cached -e <фрагмент-ключа>
```

и **не коммитить, если нашлось**. Однажды ключ уже уехал в историю вместе с
`dist-web/`, потому что проверка печатала предупреждение, но не блокировала.
`dist-web/` в `.gitignore`.

## Грабли NoiseModelling

Полный список с пояснениями — в README, раздел «Грабли». Самое ходовое:

- Сигнатуры `exec` у блоков различаются: часть принимает `(Connection, input)`,
  часть имеет перегрузку с `ProgressVisitor`. Лишний аргумент — `MissingMethodException`.
- Нужен `Delaunay_Grid`, а не `Regular_Grid`: `Create_Isosurface` потребляет
  таблицу `TRIANGLES`, которую создаёт только он.
- **Дифракция выключена по умолчанию.** Без неё двор равен улице по уровню, и
  карта вырождается в «расстояние до дороги».
- `confMaxSrcDist` по умолчанию 150 м — дальние магистрали молча выпадают.
- Результат выходит в метрической проекции, для веба нужен `Change_SRID` в 4326.
- `CREATE TABLE AS SELECT` в H2 оставляет колонки nullable, первичный ключ на них
  не встаёт — сначала `SET NOT NULL`.

## Кэш

Ключ кэша считается от округлённых координат **и параметров расчёта** (`JOB_PARAMS`).
Изменение любого параметра — радиуса, дифракции, рельефа — делает весь кэш
недостижимым, и демо-точки нужно **прогревать заново**.

Округление до сетки обязано быть идемпотентным: шаг по долготе считается от уже
округлённой широты. `check-quantize.mjs` проверяет это на ~88 тысячах точек;
запускайте после любой правки `quantize`.

## Фронтенд: что легко сломать

- **Отступ карты под панель измеряется**, а не выводится из брейкпоинта
  (`usePanelMargin.ts`). Высота панели зависит от содержимого, положение
  переключается между нижней панелью и боковой колонкой.
- `margin` применяется в момент установки позиции, а не при своём изменении.
  Поэтому пересчёт центра висит на `resize` — и **не должен** висеть на изменении
  `margin`: панель растёт от прогресса и результатов поиска, камеру будет дёргать.
- Полоса прогресса **не должна обгонять подтверждённое сервером** больше чем на
  несколько процентов. Отчёты приходят раз в десятки секунд; ощущение живости
  даёт локальный счётчик секунд, а не выдуманный прогресс.
- В `.app` только карта растягивается на 100% высоты. Правило `.app > *` уже
  однажды раздуло панель на весь экран.

## Ж/д ветка не работает

`--rail` выключен по умолчанию и к серверу не подключён. Извлечение путей и расчёт
эмиссии работают, **проход распространения не завершается** за разумное время.
Трамваи невозможны в принципе: в каталоге CNOSSOS их нет. Подробности и замеры —
в README. Не считайте эту ветку рабочей и не включайте по умолчанию.

## Как здесь принято работать

- **Измерять, а не утверждать.** Любое «стало быстрее» или «точнее» подкрепляется
  цифрами до и после; для этого и существуют `compare-runs.mjs`, `sanity-check.mjs`.
- **Проверять посылку до реализации.** Перед рельефом был замерен перепад высот,
  перед ж/д — содержимое каталога и покрытие тегов в OSM. Одна из двух задач после
  этого была свёрнута.
- **Отрицательный результат записывать.** Разрежение сетки рельефа не даёт
  выигрыша — это в README, чтобы не пробовать повторно.
- **Честно помечать непроверенное.** Образ Docker не собирался, и это написано
  прямо в README и в шапке файлов.
- Комментарии в коде — **на английском**, README, CLAUDE.md и сообщения коммитов —
  **на русском**.
- Комментарии объясняют «почему», а не «что». Особенно ценны те, что фиксируют
  неочевидный выбор: почему `fence`, почему второй проход, почему не `startsWith`.
